Validación de vulnerabilidades comunes

Las pruebas de seguridad buscan identificar debilidades en el software que puedan ser explotadas por atacantes. Entre las vulnerabilidades más frecuentes se encuentran:

  • SQL Injection: ocurre cuando un atacante inserta código SQL en campos de entrada para manipular la base de datos. Ejemplo: introducir ' OR '1'='1 en un formulario de login para acceder sin credenciales válidas.
  • XSS (Cross-Site Scripting): se da cuando un atacante inyecta scripts maliciosos en páginas web, afectando a otros usuarios. Ejemplo: un comentario en un foro que contiene <script>alert('hack');</script>.
  • CSRF (Cross-Site Request Forgery): engaña al usuario para ejecutar acciones no deseadas en una aplicación en la que ya está autenticado.
  • Validación de entradas: el QA debe verificar que el sistema filtre y sanitice correctamente los datos ingresados por el usuario, evitando que se conviertan en vectores de ataque.

La validación de estas vulnerabilidades es esencial en aplicaciones críticas como banca, salud y comercio electrónico, donde un fallo puede comprometer datos sensibles.

Herramientas: OWASP ZAP, Burp Suite

Para detectar vulnerabilidades, el QA se apoya en herramientas especializadas:

  • OWASP ZAP (Zed Attack Proxy):
    • Proyecto de código abierto respaldado por OWASP.
    • Permite realizar análisis dinámicos de seguridad en aplicaciones web.
    • Funcionalidades: escaneo automático de vulnerabilidades, interceptación de tráfico HTTP/HTTPS, pruebas de fuzzing.
    • Ventaja: gratuito y ampliamente usado en entornos académicos y profesionales.
  • Burp Suite:
    • Herramienta comercial muy utilizada en pruebas de penetración.
    • Ofrece un conjunto completo de utilidades: proxy de interceptación, escáner de vulnerabilidades, repetidor de solicitudes y comparador de respuestas.
    • Ventaja: interfaz intuitiva y capacidad de personalización mediante extensiones.
    • Versión Community gratuita y versión Professional con funcionalidades avanzadas.

Ambas herramientas permiten al QA simular ataques reales y validar la robustez del sistema frente a amenazas externas.
