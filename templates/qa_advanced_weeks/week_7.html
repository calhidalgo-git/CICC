Conceptos de carga, estrés y escalabilidad

Las pruebas de rendimiento permiten evaluar cómo responde un sistema bajo diferentes condiciones de uso. Los tres conceptos clave son:

  • Pruebas de carga:
    • Simulan un número creciente de usuarios concurrentes para medir el tiempo de respuesta y la estabilidad del sistema.
    • Objetivo: verificar si la aplicación soporta la carga esperada en condiciones normales de operación.
    • Ejemplo: simular 500 usuarios accediendo simultáneamente a un portal de e-commerce durante una campaña de descuentos.
  • Pruebas de estrés:
    • Llevan el sistema más allá de su capacidad máxima para identificar puntos de falla.
    • Objetivo: evaluar cómo se comporta la aplicación en situaciones extremas y si se recupera adecuadamente después de la sobrecarga.
    • Ejemplo: incrementar usuarios hasta que el servidor colapse y analizar el tiempo de recuperación.
  • Pruebas de escalabilidad:
    • Validan si el sistema puede crecer en recursos (hardware, instancias en la nube, balanceo de carga) sin perder rendimiento.
    • Objetivo: comprobar que la arquitectura soporta expansión y que el sistema mantiene tiempos de respuesta aceptables al aumentar la capacidad.
    • Ejemplo: añadir más nodos a un clúster y verificar que el sistema distribuye correctamente la carga.

Estos tres tipos de pruebas permiten asegurar que el software sea rápido, estable y capaz de crecer según las necesidades del negocio.

Herramientas: JMeter, Gatling

Para ejecutar pruebas de rendimiento, el QA se apoya en herramientas especializadas:

  • Apache JMeter:
    • Herramienta de código abierto ampliamente utilizada.
    • Permite simular múltiples usuarios concurrentes enviando peticiones HTTP, JDBC, SOAP, REST, entre otras.
    • Ventaja: interfaz gráfica intuitiva y soporte para pruebas distribuidas.
    • Ejemplo: crear un plan de prueba que simule 1,000 usuarios realizando compras en un sitio web.
  • Gatling:
    • Framework moderno basado en Scala, orientado a pruebas de rendimiento de aplicaciones web.
    • Destaca por su eficiencia en el consumo de recursos y su capacidad para generar reportes detallados en tiempo real.
    • Ventaja: scripts fáciles de mantener y ejecución rápida, ideal para integrarse en pipelines CI/CD.
    • Ejemplo: validar el tiempo de respuesta de una API bajo 10,000 solicitudes concurrentes.

Ambas herramientas permiten al QA medir la capacidad del sistema y detectar cuellos de botella antes de que afecten a los usuarios finales.
